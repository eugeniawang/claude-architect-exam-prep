# Review System

This course uses a layered review system so skills stick and not just familiarity.

## Session Opener

Every resumed session should open like this:

1. Read `learner/learning-log.md`.
2. Find items where `Next Due <= today`.
3. If anything is due:
   - run 1 or 2 short review MCQs per due concept
   - drill any matching watch-list item
   - update confidence and next due date
4. Only then move into new review material.

## Review Rhythm

For each new concept, use this sequence:

1. Explain
2. Feynman check
3. Scenario quiz
4. Notes/log update

This should feel cumulative:

- Week 1: identify and explain
- Week 2: configure and choose
- Week 3: critique and validate
- Week 4: apply under mixed scenario pressure

## Confidence Ratings

| Rating | Meaning | Next interval |
|--------|---------|---------------|
| Weak | Could not explain core mechanism or chose the wrong answer | 1 day |
| Hesitant | Right but shaky, partial reasoning, or poor distractor diagnosis | 3 days |
| Confident | Clear explanation, correct scenario choice, good anti-pattern reasoning | 7 days on first pass, then double |

## Watch List

Track precise gaps, not vague ones.

Good:
- `confuses tool_use with assistant text completion`
- `uses prompt instead of hook for refund limit`

Bad:
- `Domain 1 weak`

## End Goal

The learner should not just remember definitions. They should:

- choose the correct action in a realistic scenario
- explain why tempting alternatives are wrong
- link the answer to the official domain/subdomain
